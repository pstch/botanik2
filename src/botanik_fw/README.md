# botanik_fw - Arduino OPTA firmware

Hardware counterpart of [botanik_sim](../botanik_sim/README.md). Where the simulator
runs the library as a Linux process, this builds it into a flashable OPTA image via
the Arduino toolchain
(**Route A**: let `arduino-cli`/the IDE own the link + sign + upload, using the
bundled Mbed core under `includes/`).

## Layout

| File | Role |
|---|---|
| `botanik_fw.ino` | Thin sketch entry: the core's `main()` calls `setup()`/`loop()`; both defer to a function-local-static `BotanikFirmware`. |
| `firmware.h` | PLC payload stubs + site pages + the `BotanikFirmware` aggregate. |
| `firmware.cpp` | Construction (the `setup()` work) and the per-tick `step()`. |

The `setup()`/`loop()` wiring mirrors `botanik_sim/main.cpp`, minus the simulator-only
plumbing (raw-console HAL, signal handlers, `make_process_realtime`, the emulator
thread). The PLC shared memory is bound from `HAL::get_plc_input()/get_plc_output()`
rather than allocated locally.

## Placeholders

`PlcInputData_t` / `PlcOutputData_t` in `firmware.h` are **stubs**. The real layout
is generated by the PLC IDE and shared byte-for-byte with the M4 coprocessor;
replace them with the generated types and verify with the `static_assert`s noted in
`botanik_sim/simulator.h`. Until then the firmware links and the home page renders
a minimal temperature/humidity readout.

## Building (Route A)

Requires `arduino-cli` (or the Arduino IDE) with the OPTA core installed - neither
is present in this checkout yet, so the steps below are **not yet validated here**.

```bash
arduino-cli compile --fqbn arduino:mbed_opta:opta src/botanik_fw
arduino-cli upload  --fqbn arduino:mbed_opta:opta -p /dev/ttyACM0 src/botanik_fw
```

`arduino-cli` handles the parts the CMake `build-opta` target deliberately skips:
preprocessing `linker_script.ld`, linking whole-archive against `libmbed.a`, MCUboot
signing via `imgtool`, and upload. It also compiles *our* sources with the variant's
exact flags, so the float-ABI/define mismatches that block a hand-rolled link don't
arise.

**Open wiring item:** the sketch must see `libbotanik` as a compilable unit.
`arduino-cli` compiles the sketch folder plus a `src/` subfolder recursively, not an
arbitrary external tree - so `libbotanik` needs to be exposed as an Arduino library
(a `library.properties` + a `src/` that resolves to `src/libbotanik`, e.g. via a
symlinked `libraries/libbotanik` passed with `--libraries`). To be finalized and
verified once `arduino-cli` is available.

## CMake `build-opta` is still the fast path for ABI/size checks

`cmake -B build-opta -DBOTANIK_TARGET=OPTA` compiles `libbotanik` for ARM (size +
LTO + footprint `static_assert`s) without the full Arduino link. Keep using it for
quick "does it still build for the target" checks; use Route A to produce a `.bin`.
